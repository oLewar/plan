# Quality Scoring Framework

Универсальная система оценки качества решений с настраиваемыми профилями.

## Проблема

Нет единого способа оценить:
- Насколько хорошее решение принял агент?
- Насколько качественное code review?
- Насколько хороший UX?
- Насколько эффективна собственная работа?

При этом метрики **не должны быть одинаковыми для всех доменов** — у каждого контекста свои принципы, веса и пороги.

## Идея

**Профиль оценки (Scoring Profile)** — набор:
- **Принципов** (что считается хорошим)
- **Метрик** (что измеряем, шкала 1–5 или 1–10)
- **Весов** (какие метрики важнее)
- **Порогов** (минимально допустимый уровень)
- **Контекста** (для кого/чего этот профиль)

## Целевые профили (первая очередь)

### 1. UX Quality
Оценка интерфейсных и пользовательских решений.

Примеры метрик:
- Ясность (clarity) — понятно ли пользователю что делать?
- Консистентность (consistency) — единообразие паттернов
- Эффективность (efficiency) — минимум шагов до результата
- Обработка ошибок (error handling) — что видит пользователь при сбое?
- Доступность (accessibility) — A11y compliance
- Эстетика (aesthetics) — визуальная чистота

### 2. Code Review Quality
Оценка качества ревью кода (как человеком, так и агентом).

Примеры метрик:
- Покрытие (coverage) — все ли изменения просмотрены?
- Глубина (depth) — найдены ли логические ошибки, а не только стиль?
- Actionability — конкретность замечаний (не «плохо», а «сделай X потому что Y»)
- Безопасность (security) — проверены ли уязвимости?
- Тесты — проверено ли покрытие тестами?
- False positive rate — сколько замечаний бесполезных?

### 3. Agent Decision Quality
Оценка решений, принятых AI-агентами.

Примеры метрик:
- Корректность (correctness) — решение правильное?
- Полнота (completeness) — все аспекты задачи учтены?
- Эффективность (efficiency) — минимум шагов/токенов/времени?
- Безопасность (safety) — нет побочных эффектов?
- Верификация (verification) — результат проверен?
- Соответствие (alignment) — совпадает с намерением пользователя?

### 4. Self-Assessment (самооценка)
Оценка собственных решений и действий.

Примеры метрик:
- Фокус — работал ли я над самым важным?
- Причинность — понял ли я корневую причину?
- Действенность — привело ли решение к результату?
- Время — уложился ли в разумные рамки?
- Обучение — чему научился?

## Архитектура (черновик)

```
scoring-profiles/
├── ux-quality.yaml
├── code-review.yaml
├── agent-decision.yaml
├── self-assessment.yaml
└── _template.yaml
```

Каждый `.yaml` содержит:
```yaml
name: ux-quality
version: 1
description: Оценка качества UX решений
context: UI/UX design decisions, wireframes, prototypes

metrics:
  - name: clarity
    description: Понятно ли пользователю что делать
    weight: 0.25
    scale: 1-5
    threshold: 3
    
  - name: consistency
    description: Единообразие паттернов и компонентов
    weight: 0.15
    scale: 1-5
    threshold: 3

scoring:
  method: weighted_average  # или threshold_gate, multi_criteria
  pass_threshold: 3.5
  
output:
  score: float       # итоговый балл
  grade: A-F         # категория
  findings: list     # конкретные замечания
  recommendations: list  # что улучшить
```

## Способ применения

1. **Ручная оценка** — Chappy применяет профиль к артефакту и выдаёт scorecard
2. **Автоматическая** — встроить в CI/Kanban как gate перед завершением задачи
3. **Сравнительная** — оценить несколько вариантов одним профилем и выбрать лучший
4. **Ретроспективная** — оценить прошлые решения для калибровки
